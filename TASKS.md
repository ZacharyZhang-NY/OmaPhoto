# Compositor for Linux — task list

This file is the progress truth. Work top to bottom. Do not skip. One item at a time, main agent only.

## Ground rules

- No PRD exists. Chapters follow the README feature sections; order bends only where a dependency forces it.
- The Swift tree is the spec and stays untouched. Each Swift file gets a Linux twin with the same type and function names.
- Swift files over 500 lines split by concern with the repo's own `Name+Part` convention.
- Done means: code, twin tests green in the dev container, codex review passed (max 3 rounds), box ticked.
- A failed third round ends an item's reviews. Its findings are fixed, proven by tests and mutants, logged as such, and named in the next item's review scope.
- Review: Herdr split pane, codex agent `reviewer` on `gpt-6-astra` at effort `max` in YOLO mode, scoped to the item's files. The user's shell aliases `codex` to `codex --yolo`, so the pane start passes only `-m gpt-6-astra -c model_reasoning_effort="max"`.
- No commits unless the user asks.

## Decisions (user-confirmed 2026-09-20)

- Stack: C++20, Qt 6 Widgets (floor: Qt 6.4, Ubuntu 24.04). CPU raster: QPainter plus the eight C kernels, compiled in place from `Compositor/Rendering/*.c`.
- Remove Background: ONNX Runtime with an open-licensed model.
- No updater on Linux. No Dokploy. Final output: packages and the acceptance table.
- Omarchy source: `~/.local/state/omarchy/current/theme/colors.toml` (Omarchy 4.x). Absent file means built-in dark. Omarchy 3.x is out of scope.

## Cut (razor)

GPU backend (unless item 8.3 fails its gate), AppImage, Flatpak, CI pipelines, theme plug-ins, theme settings UI.
